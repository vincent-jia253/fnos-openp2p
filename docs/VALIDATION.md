## 3. 方法：让"通过"意味着什么

1. **每条新断言都配对照组**——共 **26 组**（含冻结快照 `-1`/`-6`/`-8`/`-9`/`-10` 的 `cmd/`）。对照组的形式是"旧版本 / 机械变异体必须变红"，
   例如：把修复处的代码回退成修复前写法，用例必须失败；否则该用例无鉴别力，不算通过。
2. **变异体必须先过语法检查**（`bash -n`）。这条是被教训出来的：
   曾用 `sed` 做变异时吞掉了 `; fi`，变异体本身语法就坏了，
   于是"对照组没复现"被误读成"用例无鉴别力"。
3. **用例必须能区分"没走进被测分支"与"走进且表现正确"**——
   两者的日志形态不同，否则一个恒真的断言也能"通过"。
4. **证据索引由脚本生成，不手写**：索引把每个结论绑定到具体文件哈希，
   `--check` 可自检"索引是否还在说真话"；并用两次"让它说谎"实验（改内容 / 只改 mtime）
   验证 `--check` 真的会报 diff 并非零退出。
5. **独立复核**：交付前由一名**独立 QA**做多轮对抗性复核：
   逐字节对拆两个包、自写 harness 重放关键用例、对每条修复自造回退变异体。
   其中第 6 轮裁定「有条件通过，阻塞项 0 条」；第 7 轮（对 `-9`）**发现 1 条阻塞项**
   （`-9` 只修好了"锁目录建不出来"，"锁目录删不掉"仍是忙等死循环）**并当场被写进回归**——
   即块 I 的 `I4`，对照组实测旧实现 `timeout` 12 秒不返回。
   随后对 `-10` 做**定向复验（第七轮 b）**：裁定「有条件可以给陌生人用，阻塞项 0 条」，
   B3' 与 N5–N10 逐条实测生效，另挖出 N11–N14 四条非阻塞项（已在 `-11` 修掉，见 §5）。
   报告：`docs/qa-review-round5.md`、`qa-review-round6.md`、`qa-portability-review.md`、
   `docs/qa-round7-review.md`。

## 5. 已知未闭环 / 限制（诚实清单）

**未验证（沙箱或权限不可达）**：

- **整机重启后的自启留存**——开发机在整个验证期内没有重启过（`uptime`/`last reboot` 可证），
  所以"重启后能自己起来"这条**没有证据**，不能算通过。
- **armv7 / armv8l 设备上的原生执行**（仅在 x86_64 宿主用 qemu 验证）
- **i386 原生执行**：qemu 与上游官方 386 构建在该环境下同时崩溃，属环境限制，非包损坏；
  包内自检（`$cand -v`）会在真 i386 设备上 fail-fast，不会静默装一个跑不起来的应用
- **应用中心向导 UI 的实际渲染**（`password` / `radio` / `rules` 控件的观感）
- **`platform=all` 在应用中心的架构匹配行为**
- **磁盘写满（ENOSPC）时**保存设置/写配置的表现

**已登记的低危残余**（不影响使用，已知未修）：

- 数据目录收紧函数在 `chmod` 失败时静默返回，注释口径高于实际保证
- 3 处仍使用裸 `mkdir`（随后同路径会被收紧，非真实缺口）
- `index.cgi` 中有两处目录收紧逻辑是内联重复实现，未复用函数（漂移风险）
- `config.json.bak` 在目录收紧前由 `cp` 创建，而该文件系统上 `cp` 会把 `600` 放宽为 `755`
  （真机目录本身是 `700`，因此当前不成立）
- 界面日志对"非法输入"只报长度不回显内容，但节点名等非敏感字段仍会回显
- `config.json` 合法但没有 `network` 段时，原文件会被保留为 `config.json.broken`、
  活动配置换成最小配置（不丢数据，但手写的 `apps[]` 不在生效配置里）
- 锁的"陈旧"按目录 mtime 判定；属主进程存活时已不会夺锁，但属主记录缺失的超长持锁仍可能被接管

**`-10` 新修并已回归的项**（对应第七轮评审 B3' 与 N5–N10）：

| # | 问题 | 修法 | 回归 |
|---|---|---|---|
| B3' | 陈旧锁 + 锁目录删不掉 → 忙等死循环（`rm` 失败后 `continue` 跳过计时与 sleep） | 只有"真删掉"才立即重试，失败则计入 120 秒总时限并限频告警 | I4a–I4d（对照组 rc=124） |
| N5 | 卸载白名单 `$APPDIR/*` 过宽，能删掉 `target/` | 收窄为精确形态 `$APPDIR/shares/<app>` | I5a（对照组删掉了 `target/`） |
| N6 | `$APPDIR` 是符号链接时"删配置"被误判为拒绝（Token 留存） | 比对前对两侧都做 `readlink -f` 规范化 | I5b（对照组留 Token） |
| N7 | `config.json` 是符号链接时被换成普通文件，原目标不再更新 | 写前解析到链接目标 | I5c（对照组脱链） |
| N9 | 超龄锁即使属主进程还活着也会被夺走（正好制造重复实例） | 属主 PID 存活则绝不夺锁 | I5d（对照组夺锁） |
| N10 | 锁路径被普通文件占用 → start/stop 被永久挡住，只能人工删 | 主动清理该文件（清不掉才快速失败） | I5e（对照组永久挡住） |

**本轮（`-11`）新修并已回归的项**（对应第七轮 b 的 N11–N14）：

| # | 问题 | 修法 | 回归 |
|---|---|---|---|
| N11 | 锁属主记录被 FIFO / `/dev/zero` / 符号链接占用时，`cat <` 永久阻塞 → `start` 挂死（锁目录 `mkdir` 受 umask 影响，别人可能在这塞东西） | 读之前先判 `[ -f "$f" ] && [ ! -L "$f" ]`，且用 `head -c 32 … | tr -dc 0-9` 有界读取；拿到锁后 `chmod go-rwx "$LOCK_DIR"` | I6a（对照组 rc=124 挂死） |
| N12 | 属主记录缺失时 stderr 泄漏 `${LOCK_DIR}/owner: No such file or directory`（N11 补丁引入的回归） | `head -c 32 "$f" 2>/dev/null`（**重定向写在命令最前**，否则 `2>` 只作用于管道末端） | I6b（对照组多出 stderr 行） |
| N13 | 注入点 `O2P_LOCK_MAX_TICKS` 填入超长数字（> INT64_MAX）时 `[` 报 `integer expression expected` → 超时判据失效，永不返回且每 0.2 秒刷一行错误 | 先校验位数（`≤4`）再校验数值（`≤600` 且为整数），不合法一律回落 600 | I6c（对照组 rc=124 + 海量 stderr） |
| N14 | `config.json` 是指向数据目录**之外**（如 `/tmp`）的符号链接时，Token 被写到外部文件 | 解析出真实路径后校验必须落在 `$(real_data_dir)/` 之内，否则拒绝写并记日志 | I6d（对照组写到 `/tmp`） |
